# 004. 記録を受け取ったら、ABS の今の進捗と比べてから反映する

- 状態：採用
- 日付：2026-10-17
- 関連：[仕様](../spec.md) 5.1 節・7 章（元の論点 B1）

## 状況

AntennaPod は、聴いた記録（POST）を goPodder へ送る。ブリッジはそれを中継したあと、ABS の進捗にも反映する。反映するかどうかは「更新時刻が新しい方を正とする」ルール（7 章）で決めるが、最初の仕様では、POST のときに ABS の今の進捗を取得する手順がなかった。

AntennaPod はオフラインの間も記録を溜め、つながったときにまとめて送る。たとえば次の流れで困る。

1. 朝、オフラインの AntennaPod で 10 分まで聴く（記録は端末に溜まる）
2. 昼、ABS の Web 画面で続きを 30 分まで聴く
3. 夜、AntennaPod がつながり、朝の「10 分」の記録を送る

ABS の状態を見ずに反映すると、ABS の 30 分が 10 分で上書きされ、昼に聴いた分が失われる。

## 選択肢

- (a) POST でも ABS の進捗を取得し、更新時刻を比べてから反映する
- (b) 比べずに、常に ABS へ反映する

## 決定

(a) を採る。進捗の取得に失敗したら、ABS へは反映しない。

## 結果

- 上の例では「ABS の方が新しい」と分かるので上書きしない。ABS の 30 分は、次に AntennaPod が同期したとき（GET）に AntennaPod へ届く。
- POST のたびに、ABS への問い合わせが 1 回増える。
- 取得に失敗して反映しなかった記録も、次の GET の突き合わせで改めて同期される。
