# 001. フィード URL の対応づけだけ管理者トークンを使う

- 状態：採用
- 日付：2026-10-17
- 関連：[仕様](../spec.md) 3.2 節・6.2 節・10.1 節（元の論点 B7）

## 状況

AntennaPod を ABS の RSS フィードで購読すると、記録のエピソードは `/feed/{slug}/item/{ID}/media.mp3` のような URL で届く。この `{ID}` は ABS のエピソード ID ではなく、フィードを開いたときに割り当てられる「フィード用の ID」で、索引のエピソード ID とは一致しない（ABS v2.33.2・v2.37.1 のソースで確認）。

フィード用の ID とエピソードを結びつけられる API は `GET /api/feeds` だけで、これは管理者専用（管理者以外には 403）。開いている全フィードについて、フィード用の ID と音声ファイルのパス（`fullPath`）を返す。

## 選択肢

- (a) `ABS_TOKEN` を管理者のトークンに限り、`GET /api/feeds` で対応づける
- (b) 公開されている RSS を取得し、タイトルや公開日で対応づける
- (c) フィード URL での照合をやめ、ABS のフィードで購読するクライアントには対応しない
- (d) 対応づけ（`GET /api/feeds`）だけを管理者のトークンで行い、ほかは一般ユーザーの `ABS_TOKEN` を使う

(b) はタイトルや日付が重なると誤るため不確実。(c) は主な使い方（ABS のフィードで購読）を捨てることになる。(a) は動くが、すべての操作が管理者の権限で行われる。

## 決定

(d) を採る（利用者の提案）。

- `ABS_ADMIN_TOKEN` を任意の設定として追加し、`GET /api/feeds` の 1 か所だけに使う。
- `GET /api/feeds` の `fullPath` を、一般ユーザーの索引にあるエピソードの `audioFile.metadata.path` と完全一致で突き合わせる。**一般ユーザーの索引にあるエピソードとだけ**対応づける。
- `ABS_ADMIN_TOKEN` がないとき、または `GET /api/feeds` が失敗したときは、照合の手順 1（フィード URL）だけを飛ばし、手順 2・3 へ進む。

## 結果

- ABS のフィードで購読したエピソードも照合できる。
- `GET /api/feeds` はアクセス権に関係なく全フィードを返し、進捗の更新（PATCH）もライブラリへのアクセス権を確かめない。一般ユーザーの索引で絞ることで、そのユーザーが見られないエピソードの進捗を書き換えないようにしている。
- ABS の API キーは持ち主の全権限を持ち、キーごとに権限を絞れない。管理者のトークンを使う場所を 1 か所に限ることで、影響を小さくしている。
- 一般ユーザー自身が管理者なら、`ABS_TOKEN` と同じ値を設定してよい。
