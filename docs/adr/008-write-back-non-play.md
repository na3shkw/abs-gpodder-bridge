# 008. 再生以外の記録のエピソードにも書き戻す

- 状態：採用
- 日付：2026-10-19
- 関連：[仕様](../spec.md) 5.2 節・7 章・10.2 節（元の論点 B12）

## 状況

goPodder（cbrgm/gopodder 21e868b = v1.4.1）は、「ユーザー・番組の URL・音声ファイルの URL」ごとに記録を 1 件だけ持つ。新しく受け取った記録で、種類（再生・ダウンロード・削除など）や時刻に関係なく上書きする（`gopodder/pggen/queries.sql` の `UpsertEpisode`）。仕様が想定していた「エピソードごとの再生の履歴から最新を選ぶ」という前提とは違った。

AntennaPod は、ダウンロードしたとき「ダウンロード」、ファイルを消したとき「削除」の記録も送る。たとえば次の流れで困る。

1. AntennaPod でエピソードをダウンロードする（goPodder の記録は「ダウンロード」）
2. AntennaPod では聴かずに、ABS の Web 画面で 20 分まで聴く
3. AntennaPod が同期する。goPodder にこのエピソードの「再生」の記録がないので、突き合わせの対象外になり、ABS の 20 分が AntennaPod に届かない

聴き終えて自動で削除されたエピソードも、記録が「削除」になり、以後は対象から外れる。

## 選択肢

- (a) 今のまま。突き合わせは、goPodder の記録が「再生」のエピソードだけ
- (b) goPodder にどんな種類の記録でもあれば、そのエピソードを「AntennaPod が知っている」とみなす。ABS → goPodder の書き戻しは種類を問わず行い、goPodder → ABS の反映は今までどおり「再生」の記録だけ

## 決定

(b) を採る。

- 再生以外の記録は、時刻を「どの時刻よりも古い」とみなす。ABS に進捗があれば、常に ABS → goPodder に書き戻す。
- 書き戻す記録の URL と GUID は、その記録から取る。
- 再生以外の記録が複数あるときは、goPodder から届いた配列の最後のものを使う（実装者が決め、2026-10-26 に利用者が承認）。時刻は使わないので、どれを選んでも結果は変わらない。

## 結果

- 上の例で、ABS の 20 分が AntennaPod に届く。「ABS の Web 画面で聴き始めて、AntennaPod で続きを聴く」という使い方（10.3 節の拡張予定）の一部を、追加の仕組みなしで満たせる。
- goPodder は、時刻だけが違う同じ内容の記録を保存し直さない。また、受け取ってから 90 日（既定）経った記録を削除する。長く触れていないエピソードは対象から外れるが、実害は小さいので注記にとどめた。
- goPodder v1.4.0 より前は、同じ内容の記録も保存し直す（b0dca1e）。v1.4.0 以上で使う前提。
