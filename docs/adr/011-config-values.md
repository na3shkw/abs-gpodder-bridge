# 011. 設定値の扱い

- 状態：採用
- 日付：2026-10-17（B5）、2026-10-19（C7）、2026-10-26（実装者が決めた点）
- 関連：[仕様](../spec.md) 2.1 節・8 章（元の論点 B5・C7）

## 状況

- **goPodder を待つ時間**（B5）：goPodder につながらないときは 502 を返すと決まっていたが、待つ時間がなかった。ABS には 5 秒（`ABS_TIMEOUT_SECONDS`）がある。goPodder が固まると、ブリッジがいつまでも待ち、AntennaPod 側のタイムアウトまで同期が終わらない。
- **任意の変数の不正な値**（C7）：仕様には「必須の変数が未設定、または値が不正なら起動をやめる」とあったが、任意の変数（`LOG_LEVEL` など）の不正な値も含むのかが読み取りにくかった。たとえば `LOG_LEVEL=verbose` や `ABS_TIMEOUT_SECONDS=abc` と書き間違えたとき。
- **仕様に書かれていない細部**：最初の実装で、実装者が次の点を自分で決めた。

## 決定

- **B5**：`GOPODDER_TIMEOUT_SECONDS`（既定 30 秒）を追加する。クライアントのリクエストを中継するときと、ブリッジが自分から goPodder へ問い合わせるときの両方に使う。
- **C7**：任意の変数でも、値が不正なら終了コード 1 で起動をやめる。
- **実装者が決めた点**（2026-10-26 に利用者が承認。**仕様書には書かれていない**）
  - 値が空の環境変数（`LOG_LEVEL=` など）は、設定されていないものとして既定値を使う。
  - `GOPODDER_TIMEOUT_SECONDS`・`ABS_TIMEOUT_SECONDS` は 0 より大きい値だけを受け付ける（`0`・負の値・NaN・無限大は不正）。
  - `LISTEN_PORT` は 1〜65535 だけを受け付ける。

## 結果

- 書き間違いに、気づかないまま既定値で動くより、起動の時点で分かる方がよい。
- docker compose で `VAR=` とだけ書いても止まらない。
- 実装者が決めた点は e2e では確かめず、実装者が自分で書いたテスト（`internal/bridge/config_test.go`）で守られている。
