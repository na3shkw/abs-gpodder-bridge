# 016. フィード URL はパスの末尾の形で照合する

- 状態：採用
- 日付：2026-10-31
- 関連：[仕様](../spec.md) 6.2 節・10.1 節・10.3 節

## 状況

照合の手順 1（ABS のフィード URL）は、URL のパスが `/feed/{slug}/item/{フィード用 ID}/...` で**始まる**ことを前提にしていた（[ADR 001](001-feed-url-mapping.md) の時点の想定）。

実際に AntennaPod を ABS の RSS フィードで購読して動かすと、記録の URL は `http://{ホスト}/audiobookshelf/feed/{slug}/item/{フィード用 ID}/media.aac` の形で届き、手順 1 で照合できなかった。ABS v2.37.2 のソースで、次のことを確認した。

- v2.18.0（コミット「Enable subdirectory support」）から、ABS は既定でベースパス `/audiobookshelf` の下で動く。ABS の環境変数 `ROUTER_BASE_PATH` で変えられ、空にもできる（`index.js`・`prod.js`）。
- ベースパスで始まらないパスへのリクエストも、ベースパスを補って受け付ける（`server/Server.js`）。
- RSS フィードの XML に書かれる URL は「オリジン＋（リクエストのパスがベースパスで始まっていればベースパス）＋`/feed/{slug}/item/{ID}/media.{拡張子}`」になる（`Server.js` の `originalHostPrefix`、`FeedEpisode.js`）。
- ABS の Web 画面に表示されるフィードの URL には、ベースパスが付く（`OpenCloseModal.vue`）。

つまり、ベースパスが付いた形・付かない形・利用者が変えたベースパスが付いた形のどれでも届きうる。ABS の前にリバースプロキシを置いて、別のパスの下で公開することもある。

## 選択肢

- (a) パスのどこかに `/feed/{slug}/item/{ID}/` があれば照合する（ID の後ろは 1 つ以上）
- (b) パスが `/feed/{slug}/item/{ID}/{ファイル名}` で終われば照合する（後方一致）
- (c) `ABS_URL` のパスを取り除いてから、今までどおり先頭で照合する

(c) は、ベースパスがなくても ABS は動くので `ABS_URL` にベースパスが書かれているとは限らず、リバースプロキシの下でも合わない。(a) は、`/feed/…/item/…` がパスに 2 回現れたときにどちらを使うかを別に決める必要がある。

## 決定

(b) を採る（利用者の選択）。

- パスの最後の 5 つの部分が `feed`・`{slug}`・`item`・`{フィード用 ID}`・`{ファイル名}` で、`{slug}`・`{フィード用 ID}`・`{ファイル名}` が空でないときに、フィード用 ID を取り出す。それより前のパスは問わない。

## 結果

- ベースパスの有無や値、リバースプロキシのパスにかかわらず、ABS のフィード URL で照合できる。設定は増えない。
- ABS が作る形（ID の後ろがファイル名 1 つ）にだけ一致する。以前の仕様で一致していた、ID の後ろが 2 つ以上の URL（ABS は作らない）は一致しなくなる。
- 取り出したフィード用 ID が対応表にあるときだけ照合するので、ほかの配信元の URL を誤って照合するおそれは小さい。
