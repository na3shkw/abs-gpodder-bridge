# 003. ABS への進捗の送り方

- 状態：採用
- 日付：2026-10-17（C6 は 2026-10-19）
- 関連：[仕様](../spec.md) 5.3 節・10.1 節（元の論点 B8・B9・B10・C6）

## 状況

ブリッジは、goPodder の記録を `PATCH /api/me/progress/...` で ABS に反映する。ABS のソース（`MediaProgress.js` の `applyProgressUpdate`）を調べると、送り方によって次のことが起きると分かった。

1. **`isFinished: false` を送ると位置が 0 に戻る**（B8）：聴き終わったエピソードに `isFinished: false` を送ると、ABS は送った `currentTime` を捨てて 0 にする。次の同期で「ABS の位置 0 の方が新しい」と判断され、AntennaPod にも 0 が書き戻される。
2. **残り 10 秒未満で自動的に完了になる**（B9）：既存の進捗を更新したとき、`duration − currentTime < 10` なら、ABS は `isFinished` を `true` にする。
3. **`lastUpdate` は反映した時刻になる**（B10）：ABS の `lastUpdate` は、記録の時刻ではなくブリッジが反映した時刻になる。

また、ABS で聴き終わったエピソードを AntennaPod で最初から聴き直すと、長さ（`total`）のない「3 分」の記録が届くことがある（C6）。

## 選択肢

- B8：`isFinished` を常に送る ／ `true` のときだけ送る
- B9：(a) 自動の完了をそのまま受け入れる ／ (b) 本文に `markAsFinishedTimeRemaining` などを入れて抑える
- B10：(a) 今のまま ／ (b) 本文に `lastUpdate`（記録の時刻）を入れて ABS 側の時刻をそろえる
- C6：聴き直しで「聴き終わった」が外れるのを受け入れる ／ 防ぐ

## 決定

- `isFinished` は `true` のときだけ送り、`false` のときは送らない。`currentTime` が変われば ABS が自分で完了を外し、送った位置を保つ。
- 残り 10 秒未満の自動の完了は抑えず、受け入れる。仕様に注記する。
- `lastUpdate` はそろえない。
- 聴き直しで ABS の「聴き終わった」が外れるのは受け入れる。「新しい方を正とする」原則どおりだから。外すときも `isFinished: false` は送らず、位置だけを送る。

## 結果

- 位置が 0 に巻き戻る不具合を避けられる。
- 終わり際の位置を送ると ABS では完了になり、次の同期で AntennaPod にも完了（位置＝長さ）が書き戻されうる。終わり際なので、完了でそろうのは自然とみなした。
- `lastUpdate` をそろえないので、ABS の時刻は goPodder の時刻より新しくなる。ただ「同じ状態なら何もしない」という比べ方（7 章）があるので、書き戻しが繰り返されることはない。(b) は進捗の新規作成では効かず、自動の完了と組み合わさると時刻だけそろって状態が食い違うため、採らなかった。
