# 007. 聴き終わりや長さが分からないときの書き戻し

- 状態：採用
- 日付：2026-10-17
- 関連：[仕様](../spec.md) 5.4 節（元の論点 B4）

## 状況

gPodder の記録には「聴き終わった」という項目がない。ブリッジは ABS の「聴き終わった」を「再生位置＝エピソードの長さ」として goPodder に書く。長さには ABS の進捗の `duration` を使い、0 などで分からなければ長さを書かない、と決めていた。すると「聴き終わった」かつ「長さが分からない」とき、位置に何を書くかが決まらない。

これはよく起きる。ABS の進捗の `duration` は、再生アプリが送ってきた値だけが入る。ABS の Web 画面でエピソードに「聴き終わった」の印を付けると、送られるのは `{ isFinished: true }` だけで、一度も再生していなければ進捗は長さ 0・位置 0 で作られる（`User.js` の `createUpdateMediaProgressFromPayload`）。

たとえば、溜まっていた古いエピソードを聴かずに ABS の画面でまとめて「聴き終わった」にすると、AntennaPod には「0 秒まで聴いた」と伝わり、聴き終わったことが伝わらない。

## 選択肢

- ABS の進捗の位置をそのまま書く（以前の推奨）
- 長さを、ほかの情報源からも取る

## 決定

- 書き戻す長さ（`total`）は、**ABS の進捗の長さ → なければ索引にあるエピソード自体の長さ**（`media.episodes[].duration`）の順に取る。聴き終わっているかどうかにかかわらず、この取り方にそろえる。
- 聴き終わっていれば、再生位置＝長さ。聴き終わっていなければ、再生位置＝ABS の再生位置（切り捨て）。
- どちらの長さも 0 のときは長さを書かず、再生位置は ABS の再生位置を書く。

## 結果

- AntennaPod は受け取った長さ（`total`）を使わず、再生位置だけを取り込む。自分が持つエピソードの長さと比べて、終わり近くなら「聴き終わった」にする（`SyncService.java` の `processEpisodeActions`）。聴き終わったことを伝える手段は「位置を長さと同じにする」ことだけなので、この決定の意味は大きい。
- 長さをそろえて書くのは、仕様を単純にするためと、AntennaPod 以外のアプリのため。
